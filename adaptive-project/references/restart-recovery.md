# 退出应用与重新开机后的接续

适用于已有本机 项目和已获授权的原生 heartbeat。项目状态以原 `.adaptive-v4/state.sqlite3` 为准，持久原生计划以其真实 automation ID、host/thread 绑定为准。关闭应用或关机不等于用户暂停项目；用户暂停也不因重开应用而解除。

本机制是**重开后由原计划再次触发，再从持久状态接续**。它不在关机期间运行，不新增系统登录任务、常驻服务或替代计划，不承诺补跑所有错过的周期或打开应用后立即触发。机器登录后须打开桌面应用、让项目目录和原生工具可用；观察原 heartbeat 的下一次真实触发。宿主是否保留并恢复原计划必须在目标环境实测。

## 在后台提示词中保留恢复入口

首次按 [通用引导](bootstrap.md) 创建计划时，让其提示词长期包含：原项目绝对路径、安装的 skill 路径、协调 actor、授权来源，以及“每次先运行 recovery.py，按原控制、预算、截止时间和绑定恢复；不解除暂停、不重建计划、不重置用量；先对账未知派发，再在新 wake 下回收过期租约”。已有项目只更新同一计划的必要提示词，并保留其 ACTIVE/PAUSED 状态和其他设置；不为安装此能力激活原本暂停的计划。

只读检查：

```text
python -B -X utf8 PATH/TO/adaptive-project/scripts/recovery.py --project ORIGINAL_PROJECT
```

默认仅读取原绑定对应的 `$CODEX_HOME/automations/<automation_id>/automation.toml`；未设置 CODEX_HOME 时使用用户主目录下 `.codex/automations`。`--automation-root DIRECTORY` 可为独立测试或明确的本机安装指定配置目录。只支持本机 heartbeat 的平面配置格式，ID、kind、目标 thread 和 ACTIVE/PAUSED 必须能核对；格式未知、绑定不符、文件缺失或路径包含符号链接/重解析点时停止准入建议，查询真实宿主，不推测计划已激活。

输出包括原控制状态、预算/累计消耗/上限/截止时间、计划绑定、有效或过期 wake、任务租约、各状态 outbox、最近检查点、记忆版本索引及未结束验证。它不创建目录、不写数据库、不调用宿主，不发放 wake 或任务租约。退出码 0 包括正常的暂停、等待和结束；退出码 1 表示需存储恢复、对账或修正检查缺口。输出中的 `next_actions` 是建议，不能把它当作事务已经执行。

只读检查针对静止时刻；若正在提交事务或检查中内容改变，应丢弃该份计划，稍后重新检查。原生配置文件只能证明配置，不能证明应用正在运行、工具回执真实性或未来触发一定成功。

## 重开后的决策顺序

1. **完成、人工暂停、过期、预算不准入或逻辑禁用**：不做新业务。先运行 [收尾检查](shutdown.md) 的 shutdown.py，读取持久收尾意图。完成、人工暂停或整项目过期才构成整体关闭依据；仅预算不准入或逻辑禁用不能直接暂停宿主后继续验收。已关闭项目按 shutdown.prepare → 暂停原生计划 → 实际核对 → shutdown.confirm 接续，无需业务 wake；宿主要求清理时确认后再删除。中断于 prepare 与 confirm 之间时复用原意图和绑定，先查宿主，不重建计划。重开不能修改 `control.status`、`scheduler.enabled`、额度、截止时间或累计计数。暂停优先于剩余额度；到期时即使还有预算也不得自动延长有效期。
2. **原生计划 PAUSED，但项目控制仍 running**：保留宿主暂停，不因项目有待办就自动 enable。先按既有明确授权核查暂停原因；若没有恢复授权则等待用户。缺失/不匹配计划不能被当作重建许可，也不能拿新的聊天冒充原绑定。
3. **旧 wake 仍有效或尚未到期**：等待原租约或退避窗口结束，结束本轮；不盗用旧 wake 凭据、不强抢工作权。应用退出不证明所有外部子进程都停止，任务 lease 也要独立检查。
4. **inflight/unknown 派发**：查询原 host/thread 和真实工具记录。`outbox.resolve/reconcile` 可登记已发生的结果，暂停期间也可对账；缺证据时保持不确定，不重新 create/send。确认未发出才可按原事务返回 pending，之后新的派发仍累计计数。pending 从未获得派发权，后续也必须先 `outbox.begin`。
5. **原控制和宿主均允许、旧 wake 已过期或不存在**：重新读状态，使用新的请求 ID、wake ID 调用 `wake.begin`。只有实际准入成功才持新 fence 继续。原过期 wake 会在新准入时关闭，既往 wake 用量不退款；用量耗尽则停下。
6. **恢复任务和探索**：在新 wake 下用原 `recover` 事务释放过期任务，原尝试保留且旧 fence 失效；需要重做时以新 `task.claim` 领取、使用新隔离目录并累计领取次数。有效任务租约不因重开被收回。review/done 成果按原状态验收或复用；读取检查点、正式记忆来源/版本和验证计划，已经 start 的验证保留其原方法与已计成本，不重新 start 再记账。未验收旧尝试文件仅可作为候选证据。

检查和事务之间可能发生暂停、预算竞争或状态变更；原事务的当前状态、实体版本、幂等校验与 fencing 仍是最后准入依据。不要仅凭一次 `decision=ready` 执行宿主副作用。

## SQLite 中断边界

数据库采用原运行时的 SQLite 事务和 FULL 同步设置。只读检查发现 `-journal/-wal/-shm` 时拒绝读取，以免忽略尚待恢复的事务或产生隐式写入。不要删除这些文件来通过检查，也不要复制旧快照覆盖数据库。

若确认原写者已停止、路径与项目绑定无误且使用原运行时默认 DELETE journal，可执行原运行时的显式存储恢复：

```text
python -B -X utf8 PATH/TO/adaptive-project/scripts/runtime.py --project ORIGINAL_PROJECT storage-recover --acknowledge-stopped-writers
```

这是明确的物理存储维护，不能称为“纯只读检查”。SQLite 正常打开可能回滚 hot journal；普通 `status`、空写事务或 `UPDATE state=state` 仍可能留下 cold journal。此命令在 SQLite 独占写事务内校验完整性及 格式，若日志仍在，用 `PRAGMA user_version=原值` 触发 SQLite 自己完成提交清理，不手工删除日志、不切换日志模式。提交前后逐项核对 project/requests/blobs 原始内容、schema 和 user_version/schema_version/application_id 指纹相同；不创建项目业务事件，不清空或增加用量，不改变暂停、预算、有效期或幂等记录。物理数据库字节可能变化。

`--acknowledge-stopped-writers` 是调用者对已观察写者停止的声明，不是运行时自动证明所有进程已停止。不能用这个参数绕过仍在运行的代理。随后重跑 `recovery.py`，核对状态与已提交事件保留。若仍报错、使用未知日志模式/WAL 或数据库损坏，停止并保留文件与错误，不自动初始化、恢复旧备份或重置状态。

存储维护拒绝项目内 `.adaptive-v4` 路径及数据库/日志文件的符号链接、重解析点或多硬链接文件；原运行时构造时已经规范化项目根路径，因此它不证明调用者最初传入的项目根没有别名。先用只读入口检查原项目路径，操作期间不允许其他进程替换路径；本机制不是对恶意并发文件系统替换的安全隔离。

技能不能证明磁盘硬件刷新语义；进程中断测试通过不等于真实断电耐久性已验证。

## 有限真实试运行

为本次试运行单独建立项目、有限预算和截止时间。先观察真实原生触发，留下检查点、非零累计用量和未完成工作，再实际退出目标应用并重开。记录原进程退出与新进程身份、原计划和原聊天 ID、重开前后状态、随后真实 heartbeat 和新 fence，以及最终成果与宿主停止。不得用手工“继续”冒充自动恢复。

同时可在隔离对照项目预先持久化暂停状态和非零用量；在同一次应用中断前后仅检查控制、预算、截止时间及数据库字节均未改变。明确它是固定暂停对照，不把它描述为独立的真实代理项目。如果最终收尾需要显式恢复该对照，先另外说明授权和步骤，不能把它混入“自动保持暂停”的观察区间。

退出应用、终止后端、操作系统重启和断电是不同故障。报告只列实际发生的一种或几种，分别列软件故障注入、真实模型会话、宿主进程观察和未验证范围。真实关机后的接续只有实际关机、重新登录打开应用并观察原计划恢复才算通过；否则只声明协议覆盖、实测未覆盖。

## 宿主时间证据

离线时长与原生观察时间的比较使用 [宿主证据工具](host-evidence.md) 的 evidence_time.py，兼容带七位小数的 Windows 时间并保持阈值精度。保留原始字符串，不临时调用 fromisoformat 或舍入后判断通过。
