# 主动探索与证据决策

适用于方向不清、存在多个可行方案、或执行中新证据可能改变下一步的项目。使用当前实现运行时；具体字段以 [runtime.md](runtime.md) 为准。探索机制服务于研究、产品、策划、创作等领域，不预置部门或固定研究流程。

## 从模糊目标开始

保留用户原话，将可直接确定的目标、限制和授权写入章程。将 agent 的解释标为暂定：服务谁、解决什么问题、怎样衡量交付、哪些结果当前无法保证。内部可逆选择可以自行决定，目标价值取舍或缺少必要权限时再询问；不把一次模糊指令解释成无限预算或对外行动授权。

先用可访问资料找到关键未知：哪些答案可能改变方向，哪些只是完善细节。将未知关联到候选方向和验证。候选应有实质不同的路径与取舍，而不是同一方案的不同名称。可以先选择一个尚未验证的暂定方向，并明确放弃它的条件；不强制每个任务都提出固定数量的方案。

## 自主选择下一步

根据目标影响、现有证据缺口、验证成本与可逆性排序。优先做可能淘汰无效方向或解除主要阻塞的验证。精确概率不可得时用有理由的定性判断，不把任意评分当作客观事实。

每次验证先保存假设、方法、支持/反对/不确定的判据、输入来源及成本，再开始获取结果。开始后不改计划；确需改方法时记录原验证未完成或不确定，重新登记。发现无法执行也是结果，已经发生的尝试不退还探索次数。验证程序、观察数据和失败输出应作为证据保存。

实际执行前，检查 plan 与 start 的成功回执，并重读该验证确为 running；前序脚本报错、无回执或状态不符时不得继续检查。若已经误执行，保留错误和原始输出，标为未预登记观察，不补造顺序。将这部分成本单独披露，并在后续获准工作的保守成本预留中明确计入，不把额外消耗隐去；正式验证需重新登记独立方法，不能将旧结果冒充新观察。

支持结果只支持相应假设及其适用范围，不自动证明整个方向成功。反对结果可以淘汰或修正方向；不确定结果应明确缺什么证据。源文件哈希只能证明引用内容未变化，不能证明内容真实或结论正确。模拟数据、启发式评分、代理评审和真实用户测量必须分别标明。

## 选择、转向与停止

根据已有验证结果记录决策理由、替代选项、限制及下一步。暂定选择可基于假设，但不得宣称已经验证；正式证据决策需要可追溯结果。重启恢复时读当前选择、全部相关正反证据、已登记验证、预算及受影响任务，不能仅从聊天摘要继续。

转向前检查当前方向的任务：已完成成果保留；未开始任务明确继续、转移或取消；正在执行的任务按协议撤销或结束，不能让旧执行者继续提交过时方案。任务是否必须重做由具体输入和验收影响决定，不能因方向名称变化自动全部丢弃。

探索有两类结束：信息足够，转入交付；或预算、资料、权限等条件不允许继续，形成有依据的停止报告。探索预算耗尽不阻止已启动验证保存结果、决策收尾与已有成果交付，但不允许通过新候选、改名验证或新建职责重置累计消耗。预算单位是项目定义的工作额度，不是精确 token、钱或现实耗时。

## 组织与记忆

协调者管理方向和取舍，执行者完成具体调查或试验。只有持续工作量或独立核验价值才建立专职单元，不为每个候选方向固定创建一个部门。事实、假设、决策和经验分开记录；被证据推翻的判断保留来源和替代关系，不能静默覆盖。

关键决策可以安排独立核验者读取原始证据与验收标准。其任务是找遗漏、反例和不成立的推断，不只是润色结论。多数代理同意不等于有效证据。

## 交付要求

最终交付包括实际成果、如何从模糊目标形成方向、采用与放弃候选的依据、验证结果、仍未验证的效果、预算用量及下一步边界。无需暴露冗长的内部思考；保留简洁决策记录和可核查证据即可。

状态引擎只检查协议不变量：权限、版本、先计划后结果、引用、状态转移及额度。语义上的新颖性、市场价值、科学有效性和用户满意度仍需要对应证据。不得把完成流程描述为保证业务成功。
