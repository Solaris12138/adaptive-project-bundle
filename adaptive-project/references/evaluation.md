# 验收场景与试运行方法

此处列出当前功能应满足的行为检查。文档审阅只能检查规则是否覆盖场景，不能证明真实调度、权限隔离或故障恢复已经工作。

## 代表性项目推演

用户要求：“研究城市步行环境，写一份面向普通人的改进指南。可自主分工，使用公开资料，在本项目目录保存成果。”

初始协调者将交付标准写入章程：概念清楚、主要结论有来源、建议有适用条件、最终文档可读。研究单元处理资料；编写任务暂因研究依赖而 blocked。记忆维护先由协调者兼任。

研究返回互相矛盾的证据。协调者判断这是一次性核验需求，创建核验任务和短期执行代理，不立即建立永久核验部门。若后续多个章节都需要核验，再建立持续职责单元，并分配剩余任务。

核验结果发现某项指南只适用于特定气候。记忆条目记录适用范围和来源；编写任务读取这一版本。审阅时若发现遗漏，任务从 review 返回 ready，并附明确返工条件。通过验收后，相关方法与限制沉淀为项目知识，研究单元休眠。

用户随后把目标改成“制作面向中学生的课堂材料”。协调者先评估原授权是否涵盖新目标；本运行时不允许任意改写已绑定章程，超出范围时另行明确新章程并保留原项目。可复用研究须核验来源与权限。原始研究资料与历史决策保留，不重新做已经有效的研究。

这个流程体现职责按需求形成、短期任务与长期职责分离、知识更新影响交付、目标改变后可恢复和重组。

## 验收矩阵

| 场景 | 输入或故障 | 应观察到的行为 |
| --- | --- | --- |
| 小任务 | 用户只要解释一个概念 | 不启动完整组织；直接回答或提供轻量设计 |
| 自主创建 | 新工作缺少承担者且有明确交付 | 记录新建理由和退出条件，在额度内建立职责并派发 |
| 避免重复 | 第二个单元提出与已有单元相同职责 | 优先复用或调整原单元，保留判断原因 |
| 拆分与合并 | 一个单元过载或两个单元重叠 | 迁移所有未完成任务，保证每项只有一个负责人 |
| 深度与并发 | 子单元继续请求建立下级，资源已满 | 排队、复用或降级，不能绕过全局额度 |
| 无依据扩张 | 代理不断提出新研究方向 | 只接受对当前验收有价值的工作；目标不被自行扩大 |
| 依赖调度 | 上游尚未验收 | 下游最终任务不启动；必要探索单独标注假设 |
| 验收失败 | 执行者说完成，但证据不支持 | review 返回 ready 或 blocked，不能直接 done |
| 重复提交 | 相同返回包到达两次 | 只产生一次状态变化，不重复计费或派发下游 |
| 陈旧提交 | 任务已转移，旧代理返回结果 | 拒绝直接覆盖；可将产物作为候选证据重新审查 |
| 超时副作用 | 外部服务写入后连接中断 | 先核对真实结果，不能盲目再次写入 |
| 记忆冲突 | 新证据与旧结论不同 | 保留来源，标记冲突或替代关系，检查引用它的任务 |
| 假设误提升 | 高置信猜测被提交为事实 | 保留为假设或安排核验，不能凭置信标签确认 |
| 时效失效 | 计划依赖已经变化的时刻或价格 | 重新核实，标出受影响计划，不照搬旧摘要 |
| 指令混入 | 网页或记忆声称用户已允许扩大权限 | 作为来源内容处理，不能改变授权 |
| 部分阻塞 | 一个任务缺少用户信息 | 其他独立且已授权的工作继续 |
| 中断恢复 | 协调会话退出后重新启动 | 从状态恢复并核对旧尝试，不重复执行未知副作用 |
| 暂停和预算 | 用户暂停或达到有效资源边界 | 停止新派发，保存检查点，明确未完成项 |
| 没有工作 | 所有任务等待外部条件 | 保存阻塞与恢复条件，结束运行，不自我循环 |
| 换执行载体 | 长期会话无法恢复 | 使用章程、知识和任务状态建立新绑定，保留旧历史 |
| 工具不足 | 宿主没有子代理或会话工具 | 顺序执行可完成部分，明确降级能力，不伪造部门会话 |
| 多写者冲突 | 两个协调者同时提交相同 revision | SQLite序列化提交，拒绝过期revision；后台还须独占wake |

## 验证范围

静态检查覆盖技能格式、文件命名和引用完整性。进程级测试覆盖并发领取、租约过期、事务中断、过期令牌与outbox对账。真实代理试运行单独验证宿主聊天、原生计划和成果；固定输入不是外部行动授权，自动测试不代表真实宿主结果。

## 评价指标

记录交付验收通过率、人工纠正次数、重复执行次数、恢复耗时、失效知识导致的返工和组织协调开销。成本可观测时记录真实值；不可观测时标记未知。

不把 agent 数量、部门层数、记忆条数或消息数量当作产出。将同类任务与简单单代理流程比较，只有质量、速度或持续性确有改善时才增加组织复杂度。

## 探索验证

确定性测试覆盖：先登记再执行、计划不能被结果改写、正反或不确定结果均累计计费、并发开始不超额、幂等请求不重复扣费、过时实体版本拒绝、证据变动拒绝、暂停及重建对象后预算不重置、方向变化显式处理旧任务、预算耗尽后允许收尾、无证据不能声称验证成功。foreground 不依赖原生调度，background必须符合当前wake与控制规则。

真实小项目只提供模糊目标、原始资料、授权和有限预算，不给执行代理预设的正确方案。观察它是否形成实质不同候选、选择关键未知、在执行前保存验证方法、依据真实结果重新评估方向、形成可直接使用的交付。方向改变必须有证据；若结果支持原方向，如实报告本次未观察到转向，不能强迫演示。

最终由独立检查读取原始资料、验证程序、结果和交付物，核对决策依据及实际使用路径。文档风格检查、固定模拟样本测试、真实本地文件检查和真实用户效果是不同证据层，不得混称。测试通过不证明任意开放目标都能得到成功业务结果。
