# 自适应项目协作

围绕可检验的交付组织工作。职责单元、执行代理、长期聊天与持久状态分开管理，在用户授权内按需求创建、拆分、合并、休眠和恢复职责。

## 入口与模式

本发布仅使用 `scripts/runtime.py`，Python接口为 `Runtime`。任务、记忆、探索、预算和后台控制属于同一运行时。新设备先读 [可迁移安装](references/portability.md)，运行 doctor.py，并核实当前宿主工具。

- 设计与审阅：只输出方案，不启动代理、聊天或计划。读 [架构](references/architecture.md)。
- 前台运行：默认 foreground，由当前会话推进，按需委派获授权子代理。
- 后台运行：用户授权且宿主支持时选择 background，读 [调度](references/scheduling.md)、[后台适配](references/background-scheduling.md) 和 [引导](references/bootstrap.md)。
- 恢复：先核对原状态、授权、暂停、预算、绑定与未知派发。读 [恢复协议](references/restart-recovery.md)。

跨宿主时间比较或 Windows 辅助任务核验使用 [宿主证据工具](references/host-evidence.md)，权限错误保持未知，不推断已清理。

运行前读 [状态协议](references/protocol.md) 与 [运行时入口](references/runtime.md)。组织、任务、记忆查 [任务契约](references/tasks.md)；长期会话查 [会话协议](references/long-lived-chats.md)。只读取当前阶段所需资料。

## 初始化与授权

使用用户指定项目目录。有状态则先核实复用，不建立重复组织。真实目标、验收、授权来源、写入范围、有限预算和期限写入章程，通过 init/apply 提交；不得直接写SQL或将读取快照写回。

沿用 `.adaptive-v4/state.sqlite3` 与 schema 4.0 保持存储兼容，不要求用户另选版本。旧格式不自动迁移，多设备分布式写入不在本实现范围内。

按 [验收阶段预检](references/bootstrap.md#验收阶段与依赖预检) 区分业务前置与整体后置清单。charter.acceptance 不得要求 project.complete 自身或之后宿主收尾已经发生；原要求逐项保留，整体通过仍需所有后置证据。

沿用已有有效授权，不重复询问已明确事项。用户授权运行具体项目且宿主允许时，协调者主动委派有独立价值的工作。仅有子代理授权不扩大为长期聊天、未来调度或外部行动授权；安装技能也不授予这些权限。

## 工作循环

1. 读取章程、实体版本、依赖、相关记忆和资源余额，区分用户要求与假设。
2. 按能力缺口、持续工作量、并行性和核验价值调整职责。优先复用已有单元，一次性工作可直接委派。
3. 明确唯一责任单元、输入、验收、依赖、写入位置、预算和停止条件。工作者以自身绑定身份 claim，只写该次隔离尝试并续租；协调者不能冒充工作者。
4. 派发必要上下文和引用，返回成果、证据、限制、阻塞与候选记忆，不广播全部历史。
5. 核验提交，通过 task.review 接受或返工；版本冲突重读后判断，失效租约按有限恢复流程处理。
6. 记忆维护者提交 candidate，协调者核实来源后接受或替代。保留旧证据，记忆不能更改目标或升级授权。
7. 保存检查点，在完成、重大变化、需要用户决策或达到边界时汇报；有已授权可执行工作则继续。

小项目由协调者兼任探索、记忆和验收；有独立工作量再建专职职责。正式成果由数据库保存已验收权威字节，不能用可变旧工作目录替代。

## 主动探索

目标模糊时记录关键未知，形成有实质差异的候选。选择能改变决策的低成本验证，执行前登记假设、方法、判据和有限成本。结果可支持、反对或不确定，不为了交付改写判据。

按证据选择、转向、放弃或停止，显式处理受影响任务，保留原目标与授权。明确任务不需制造多余候选。见 [探索协议](references/exploration.md) 和运行时探索操作表。运行时保障记录、顺序和预算，不证明判断正确。

## 并发与恢复

SQLite事务保证领取、幂等、实体版本和 fencing token。过期 recover 后重新 claim，使用新尝试与更大令牌；旧凭据不能复活，过期不证明旧模型已经停止。

聊天创建和派发先记 outbox，再调用宿主并保存真实返回。不确定结果先对账，不盲目重建聊天。后台协调业务必须携带当前 wake 凭据，不以旧回合授权继续写入。

scripts/recovery.py 只读核查恢复条件；scripts/audit.py 在静止项目上核验租约与已验收文件。建议不是执行许可，不会启动模型、解除暂停或重置预算。示例与核验见 [使用指南](references/release-guide.md)。

## 后台控制与收尾

明确有限预算和期限，区分 operator 与 coordinator。先验证普通回合，再创建暂停态原生计划、核对真实目标聊天和协调载体容量登记、绑定，最后启用；优先复用原计划，不新建载体绕过额度。

每轮先读 plan，再申请一次 wake，做有限工作、保存检查点并结束，由宿主决定下次唤醒，不自建睡眠轮询。暂停与准入以持久状态和实时事务判断。

用户暂停时 operator 先 control.pause。按 [收尾协议](references/shutdown.md)：关闭整体业务准入 → shutdown.prepare → 暂停原宿主并核验 → shutdown.confirm → 必要时删除。仅预算耗尽或 scheduler.enabled=false 不证明所有工作已关闭，不能先停宿主再继续验收。

后台agent不得自行 resume 或提高预算。未完成收尾可无业务wake接续。运行时不能立即停止模型，也不保证精确token/金额硬上限，应分别说明工作次数预算与宿主限制。

报告进展、职责及方向调整、成果、证据、限制和未解决项。区分设计、文件生成、安装、自动测试与真实代理试运行，不把未验证效果写成成功。验证方法见 [验收场景](references/evaluation.md)。
